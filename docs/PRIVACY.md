# 隐私与数据保留策略

本项目遵循“默认不共享、按收件人共享、最少保留”的原则。新用户不会自动发送位置；加入房间也不会自动开启共享。位置共享仅面向当前已加入的房间成员，用户可以随时暂停或结束。

## 位置共享等级

| 等级 | 服务端行为 | 接收方看到的内容 |
|---|---|---|
| `hidden` | 不接受位置广播，并立即清除连接内最后位置 | 不显示位置 |
| `approximate` | 在服务端按房间与用户生成稳定偏移后映射到约 80 米网格；先转换再进入连接内存 | 约 80 米精度的位置，不含海拔、朝向或速度 |
| `precise` | 在精度不差于 100 米时转发当前 GPS 样本 | 当前经纬度及设备提供的可选运动字段 |

默认偏好是 `approximate`，但共享开关默认关闭。Twin 模拟位置使用独立的 `twin_simulated` 类型，不能通过实时房间接口伪装成 GPS。

## 数据保留与删除

| 数据 | 存储位置 | 保留时间 | 删除触发 |
|---|---|---|---|
| 实时 GPS/近似位置 | 活跃 WebSocket attachment 与客户端内存 | 仅当前连接；每人只保留最后一个已转换样本 | 暂停、隐藏、断开或房间到期时立即清除 |
| 断线成员状态 | Durable Object Storage 中的离开截止时间，不含坐标 | 15 秒重连宽限期 | 重连后取消；超时后广播离开并清除 |
| 房间、成员、房间 Pin 与评论 | D1 | 房间有效期内 | 房主删除时级联删除；到期后由每日清理任务删除 |
| 独立临时 Pin | D1 | 到 `expiresAt` | 每日清理任务删除；用户主动删除立即生效 |
| Twin 配置 | D1 | 用户保留功能期间 | 显式关闭 Twin 时保留关闭状态，避免自动恢复 |
| Twin 日程与移动计划 | D1；只含地点 ID、时间和确定性路径节点，不含 GPS 轨迹 | 模拟功能开启期间 | 显式关闭 Twin 或模拟功能时事务删除；计划随日程级联删除 |
| 审计日志 | D1 | 长期保留，用于滥用调查与操作追溯 | 仅按合规或账号删除流程处理；不写入实时坐标或消息载荷 |
| 地图编辑投稿 | R2/D1 | 审核与版本追溯所需期间 | 按投稿/账号删除流程处理 |

每日清理任务在 `03:17 UTC` 执行，因此到期 D1 数据最迟通常在下一次任务中物理删除。到期数据在清理前已经不能通过 API 或实时房间访问。

当前产品不接收图片二进制上传，只允许地图投稿引用经过校验的图片元数据，因此不存在独立图片对象的后台删除队列。将来接入图片存储前，必须先实现用户删除请求、异步对象清理和失败重试。

## 可观测性边界

运行日志采用字段白名单，只允许事件名、结果、耗时、HTTP 状态、路由、房间 ID、不可逆截断用户哈希、消息类型、精度区间和成员数。禁止记录经纬度、海拔、朝向、速度、原始用户 ID、Session、消息载荷或错误对象。具体指标与告警见 `docs/OBSERVABILITY.md`。

## 用户控制

- Web 的“隐私与共享”页面和房间共享面板使用同一份偏好；移动端在房间工具栏提供相同三级选择。
- 用户必须先选择非隐藏等级并主动开始共享；结束房间、暂停共享或连接关闭都会停止发送并清除服务端最后位置。
- 房间创建者删除房间后，成员关系和房间内容通过外键级联删除；审计记录仅保留删除动作。
